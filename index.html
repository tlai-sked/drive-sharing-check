      Setup guide

      One-time setup so this page can ask Google directly which of your Drive files are shared. About five minutes. Screenshots match the current Google Cloud console.

      You only need the Client ID. Google also shows a client secret at the end — this page never uses it, because the sign-in happens in your browser rather than on a server. Leave the secret where it is and don't paste it anywhere.

      Step 1 · Serve the page, don't double-click it

      Google refuses sign-in from a file:// address. In Terminal:

      cd ~/Downloads
python3 -m http.server 8000

      Then open http://localhost:8000/. Leave the Terminal window running while you use the page.

      Step 2 · Open a Google Cloud project

      Go to console.cloud.google.com and either create a project or select an existing one. Make sure you are signed in with your skedulo.com account, not a personal Gmail.

      Step 3 · Enable the Google Drive API

      APIs & Services → Library, search for Google Drive API, then select Enable. Without this the scan returns a permission error even though sign-in works.

      Step 4 · App information

      Go to Google Auth Platform → Overview and start the project configuration. Give the app a name and pick your support email.

      Name it something recognisable — for example Drive Sharing Check. Whatever you type here is what Google shows people on the consent screen and in error messages. An app literally named “Internal” produces the confusing message “If you are a developer of Internal…” if anything goes wrong.

      Step 5 · Audience: choose Internal

      Internal keeps the app restricted to skedulo.com accounts and skips Google's verification review. Choosing External would put it in testing mode and require adding each person as a test user.

      Step 6 · Contact information

      Your email, for Google's notices about the project. Then Create.

      Step 7 · Create an OAuth client ID

      APIs & Services → Credentials → Create credentials, then choose OAuth client ID. Not an API key, and not a service account.

      Step 8 · Web application, with localhost as an origin

      Set Application type to Web application. Under Authorised JavaScript origins add exactly:

      http://localhost:8000

      This has to match the address bar character for character, port included. localhost:3000 and 127.0.0.1:8000 are different origins to Google and will be refused. Leave Authorised redirect URIs empty.

      Step 9 · Copy the Client ID

      Copy the long ….apps.googleusercontent.com value. Ignore the client secret. Google notes that settings can take a few minutes to take effect, so if the first attempt is refused, wait a moment and retry.

      Step 10 · Paste it in and run

      Back on this page, open the gear icon, paste into Google OAuth client ID and select Save. Set your work address under Google account if you are signed into several. Then Run check and approve the Google prompt once.

      Scopes requested. Scanning uses drive.metadata.readonly — file names and sharing settings only, never file contents. Changing sharing additionally requests drive, which Google describes as full access, because there is no permissions-only write scope. That second prompt appears only when you actually change something, and the page calls nothing but the permissions endpoints. Tokens live in this browser tab and expire within the hour.

      Troubleshooting

      SymptomFix
      Error 400: invalid_request, or “Access blocked” The page is open as a file. The address bar must read http://localhost:8000, not /Users/….
      Wrong Google account signed in Set your work address in Settings, or use Switch account.
      A personal Gmail won't sign in Expected with Audience set to Internal — only skedulo.com accounts are admitted.
      Refused despite a correct client ID The authorised origin must match exactly, port included. Also allow a few minutes after creating the client.
      Sign-in works, but the scan errors The Google Drive API is probably not enabled on the project — see step 3.
      Nothing happens on Run check The browser blocked the sign-in pop-up. Allow pop-ups for localhost.

      Optional · Enable the Calendar API

      Only needed if you want Check my calendar in the planner to grey out times you are busy. It is a separate switch from the Drive API: APIs & Services → Library, search Google Calendar API, then Enable. Without it that button returns a 403 and you pick a time manually — everything else still works.

      The planner only ever reads free/busy times. Creating the event happens in Google Calendar itself, so this page never gets write access to your calendar.

      Using it on a phone or tablet

      The layout adapts to a phone screen, but there is a catch worth knowing before you try: you cannot run python3 -m http.server on a phone, and Google requires JavaScript origins to use https, with only localhost exempt. Raw IP addresses are rejected too — so pointing your phone at your laptop's http://192.168.x.x:8000 will not work.

      To use it on mobile, the page has to be hosted at an https address:

      1. Put this file on any https host — an internal web server, GitHub Pages, Netlify, Cloudflare Pages. It is a single static file, so any of them will do.
      2. In the Google console, open your OAuth client and add that address under Authorised JavaScript origins, for example https://tools.skedulo.com. Keep the localhost entry as well so desktop testing still works.
      3. Open the https address on the phone and sign in as normal.

      Once it is hosted, desktop users no longer need the Terminal step either — it becomes just a link, which is the better setup for rolling it out to the team.

      If your admin blocks new OAuth clients: ask them to create one client ID for the team and share it. A client ID is not a secret — it identifies the app, not a person. Everyone still signs in as themselves and sees only their own files.
